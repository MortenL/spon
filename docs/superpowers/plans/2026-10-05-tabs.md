# Tabs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Per-contour manual tabs (click to add, select and delete, drag), tabs on open-line profiles, slots and through pockets (as bridges to islands), and automatic placement that prefers straight edges and balances tabs around the part.

**Architecture:** `TabSettings` moves from all-or-nothing `positions` to a per-contour `manual` list (schema 10). One core helper, `contourTabs`, decides automatic or manual positions for any contour's *tab path*. Profile and slot apply tabs along the path with the existing `TabProfile`/`emitLap`. Pockets apply them as XY zones through a new writer primitive. The web app edits tabs through four new undoable commands.

**Tech Stack:** TypeScript, Vitest, React + react-three-fiber (web), Playwright, zod (MCP).

**Spec:** `docs/superpowers/specs/2026-10-05-tabs-design.md`

## Global Constraints

- `@sponcam/core` stays free of React, three.js, the DOM and Node APIs.
- Stored lengths are mm, angles degrees. Job edits go through `core/src/job/commands.ts` and the store's `commit()` so undo works.
- No new dependencies; no GPL.
- Playwright uses ports 5199 / 5198; never 5173. Never bind 5197 in tests.
- TypeScript `verbatimModuleSyntax`: `import type` for type-only imports.
- Commits use `morten.leerhoey@gmail.com` (check `git config user.email`). Push to `https://MortenL@github.com/MortenL/spon.git`; one PR per delivery phase (spec §10).
- Before claiming a task is done: focused tests, then `pnpm typecheck && pnpm test`; web changes also `pnpm build`; user flows `pnpm e2e` for the touched specs.
- Tab rule (spec §4): at levels `z < tabTop` (`tabTop = bottom + height`, strictly less) the tool rises over tabs; a tab interval covers `width + tool diameter`.

## Review Focus

1. **Geometry re-picked after manual edits:** a `manual` entry whose `refIndex` no longer exists is ignored (no crash, no tabs elsewhere); the contour at that index, if it changed, still uses its entry. (Test in Task 2.)
2. **Tool diameter changed after placing tabs by hand:** `t` fractions keep their relative positions on the new lap; tabs that no longer fit are clamped inside the lap, not dropped. (Test in Task 2.)
3. **A contour too short for a tab** (the dot of an "i", a tiny hole): auto placement skips it with `tab-skipped`; a manual tab added there is skipped with the same warning, never a crash or a NaN move. (Test in Task 2.)
4. **A stepdown level landing exactly on `tabTop`:** that level cuts normally (no lift), the levels below lift. (Test in Task 2.)
5. **A tab clicked right at a closed lap's start point (t ≈ 0 or ≈ 1):** the tab stays whole (clamped next to the seam) and is not split or duplicated. (Test in Task 4.)

## Phase 3 — smarter automatic placement (PR 3)

### Task 6: Straight-first, balanced placement

**Files:**
- Modify: `packages/core/src/cam/ops/tabs.ts` (`tabIntervals` for closed paths; open-path placement)
- Test: `packages/core/test/tabs-placement.test.ts` (new)

**Interfaces:**
- Unchanged signature `tabIntervals(path, t, toolRadius, explicitT)`; the automatic branch follows spec §5 exactly: samples every `width / 4`; straight when the direction turns < 5° over `±(width/2 + r)`; corner clearance `width` from corners sharper than 30°; centroid area-weighted; `θ₀` tried in 12 steps over `360°/n`; minimum gap `2 × width` along the path; best set = fewest curved tabs, then smallest total angular error. Open paths: `(i + 0.5) / n` of the length, ≥ `width` from ends and sharp bends, nudged ≤ half the spacing onto straight stretches.

- [ ] **Step 1: Write the failing tests**:
  - `puts one tab on each side of a rectangle`: 100 × 60 rectangle lap, n = 4 → each tab centre on a different side, none within `width` of a corner.
  - `keeps tabs on the straight edges of a rounded rectangle`: 100 × 60 with 10 mm corner radii (as arcs) → no tab centre on an arc.
  - `balances tabs around an L-shape`: L-shaped lap, n = 3 → the angles of the tab centres about the area centroid are within 30° of 120° apart, none at the re-entrant corner.
  - `falls back to the curve on a circle`: Ø50 circle, n = 4 → 4 tabs, about 90° apart (±5°).
  - `treats short facets as a curve`: the same circle as a 64-gon of lines → same as the circle, not snapped to "straight" facets.
  - `keeps the minimum gap`: n = 40 on a 100 mm square → no two centres closer than `2 × width`; the rest counted as skipped.
  - `is deterministic`: the same input twice → identical intervals.
  - `spaces tabs on an open line away from its ends`.
- [ ] **Step 2: Run** — FAIL.
- [ ] **Step 3: Implement** the algorithm (private helpers in `tabs.ts`: `tabCandidates`, `centroid`, `balancedPick`).
- [ ] **Step 4: Run** `pnpm --filter @sponcam/core test`. For every existing test whose expected tab positions change, check the new placement against the spec rule before updating the expectation; list them in the commit message.
